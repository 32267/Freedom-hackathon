# Правила снижения балла: за что снижаем, за что нет

Основа — чек-лист организаторов ([CHECKLIST.md](CHECKLIST.md)). Строки с пометкой **«трактовка»** — наше уточнение
там, где PDF не говорит явно (сверено с DEV-диалогами, см. [DATA.md](DATA.md)). Спорные пункты — в конце, их решает команда.
Эти же правила передаются модели в промпт через [`checklists/default.json`](../checklists/default.json) (поля `lower_if` / `keep_if`).

Обозначения: **Нет** — 0 баллов по критерию · ступени шкалы — как в PDF · **N/A** — критерий исключается, вес перераспределяется.

## 2. Что никогда не снижает балл

| Ситуация | Почему |
|---|---|
| Время первой реакции оператора, порог 3 минуты | Явно исключено чек-листом |
| Теги и вложения | Явно исключено чек-листом |
| Что делал или писал **бот** (приветствие, согласие на обработку данных, неверная подсказка бота) | Оценивается только оператор |
| Системные события и очередь до подключения оператора | Не действие оператора |
| Ошибки расшифровки звонка: искажённые слова, обрывки, дубли реплик, смена языка распознавания | Это ASR, а не речь оператора |
| Маскированные данные `[Имя скрыто]`, `[Персональные данные скрыты]`, `[Данные идентификации скрыты]` | Данные прозвучали, просто скрыты |
| Пауза записи звонка («Запись приостановлена») | Не знаем, что было в паузе — не додумываем ни в плюс, ни в минус |
| Клиент ушёл / бросил трубку / связь прервалась | Для «Завершения» и «Консультации» это N/A, а не Нет |
| Отказ по правилам компании (нет инвестконсультаций в поддержке) с объяснением и альтернативой | Корректное поведение |
