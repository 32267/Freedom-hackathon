## Особенности, которые учитывают промпт и UI
- **Время.** Чаты — `MM:SS` от начала. Звонки — ISO 8601 с 7 знаками долей секунды и зоной (`2026-11-03T13:49:20.0219936+00:00`).
  В данных храним как есть; в промпте показываем `ЧЧ:ММ:СС`; для плеера — `offset_sec` от первой реплики.
- **Чат начинается с бота** (приветствие AIM, согласие на обработку данных), затем `system: Эскалация на оператора` /
  `Чат операторға жіберілді` / `Chat transferred to an agent`. Приветствие бота ≠ приветствие оператора.
- **Системные события — доказательства:**
  - `Личность клиента подтверждена.` / `Клиенттің жеке басы расталды.` → критерий «Идентификация»;
  - `Оператор закрыл чат.`, `Клиент покинул чат.`, `Соединение с клиентом прервано.`, `Клиент завершил разговор.` → «Завершение» (N/A, если оборвалось);
  - звонки: `Запись и транскрибирование приостановлены/возобновлены` — часть разговора не записана.
- **Маскирование:** `[Имя скрыто]`, `[Персональные данные скрыты]`, `[Данные идентификации скрыты]` — данные прозвучали, но скрыты.
- **Звонки — автоматическая расшифровка:** искажения («Сами тебе Фридом брокер за кошки…»), смена языка kk-KZ → ru-RU,
  10 подряд идущих дублей реплик. За ошибки распознавания оператора не штрафуем.
- Последняя реплика: operator — 52, system — 10, client — 3.
- **Записи звонков:** `audio_url` отдаёт **не mp3, а HTML-страницу плеера** (`text/html`). Внутри
  `<audio><source src="https://…crm11.dynamics.com/api/filedownload/…&rsct=audio%2Fmpeg">` — подписанная ссылка на mp3,
  которая живёт **~1 час** (`se=` в ссылке). Значит: backend должен открыть страницу, достать `src` и отдавать mp3 сам
  (`GET /api/dialogs/{id}/audio` — прокси или локальный кэш), иначе `<audio>` в карточке не сможет перематывать на реплику.
  Пример разбора — `tools/export_local_dataset.py` (`resolve_audio`). Файлы: mp3, 64 kbps, 16 kHz, моно, 1.9–3.3 МБ.

## Локальная папка с данными
`python tools/export_local_dataset.py data/DEV.json` → `dataset/DEV/` (в git не попадает):
`index.md`, `chats/<id>.json|.md`, `calls/<id>.json|.md|.mp3`.
Оценки всех диалогов: `python -m backend.scoring data/DEV.json --out-dir dataset/DEV/evaluations --workers 3`
→ по файлу на диалог + `summary.md` / `summary.csv`.

## Вопросы по чек-листу — решены, см. [SCORING_RULES.md §4](SCORING_RULES.md) (ответы жюри, v5)
1. **«Выявление потребности» — Да или N/A**, если клиент сразу дал все детали и оператор ответил с их учётом,
   ничего не уточняя? (p1-ru-001 / p1-kz-001 — один и тот же диалог получил «Да» и «N/A».)
2. **«Завершение»**: «Пожалуйста. Хорошего вечера!» — прощание без итога/предложения помощи → сейчас «Нет».
3. **Звонок, где клиент бросил трубку**, пока оператор говорил, — «Нет» или N/A для «Завершения»?
