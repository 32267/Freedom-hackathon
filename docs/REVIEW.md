## Что исправить до защиты (по приоритету)

1. **Экран апелляции и очередь проверяющего** (F6) — API готов: `POST /api/appeals`, `GET /api/appeals?status=open` (с фрагментом диалога), `POST /api/appeals/{id}/decision`. В карточке — «исходно → решение → финал».
2. **Редактор чек-листа** (F5) — `GET/PUT /api/checklists/default`, после сохранения — «Оценить всё» (`/evaluations/batch` сам пересчитает только диалоги со старой версией).
3. **Карточка:** показать `checked_range` («проверен участок: реплики 3–9»), баллы секций, бейдж грубой ошибки с видом нарушения; в звонке клик по доказательству → `audio.currentTime = transcript[i].offset_sec`.
4. **Кнопка «Оценить всё» с прогрессом** (`/api/jobs/{id}`) — понадобится на контрольном наборе.
5. **Модель на финал:** для 10 примеров жюри — сильная модель (`LLM_MODEL=claude-opus-5-5`, 3 ответа ≈ $2 на все 10).

## Найдено и исправлено в коде

- `POST /api/appeals/{id}/decision` падал с 500, если чек-лист оценки удалён → теперь 404 с понятным текстом (+ тест).
- Типы: `_err` помечен как `NoReturn` (Pyright понимает ранний выход), обработчик ошибок API принимает любое исключение, CLI возвращает код выхода.
- Фронт: живой режим запрашивал `/api/evaluations/null`; ошибки API без текста; плеер звонка брал HTML-страницу вместо mp3 — исправлено при связке.

## Замечания без срочности

- `POST /api/dialogs/upload` принимает любой `audio_url`, и сервер его скачивает — для демо без авторизации допустимо, в продакшене нужен белый список доменов.
- Проверка цитат принимает очень короткие цитаты («Да»), которые встречаются везде — можно требовать ≥ 3 слов.
- Апелляция к старой (не последней) оценке меняет её, а карточка показывает последнюю — стоит запретить или явно показывать версию.
