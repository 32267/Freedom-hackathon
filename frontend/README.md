# Frontend — Freedom Broker · Контроль качества диалогов

Vanilla HTML/CSS/JS на Web Components: без npm, сборки и внешних зависимостей. Каждый экран — отдельный тег
`<cqa-*>`, поэтому его можно встроить в Dynamics 365 как HTML web resource (атрибут `api-base` у `<cqa-app>`).
Фирменные цвета — токены в начале `styles.css` (`--fb-green`, `--fb-night` …).

## Запуск
Из корня репозитория: `uvicorn backend.main:app --port 8000` → http://localhost:8000 (фронт и API с одного адреса).
Без backend: любой статический сервер из корня и `/frontend/?mock=1` — демо на `fixtures/`, только просмотр.

## Экраны
| Экран | Тег | Что умеет |
|---|---|---|
| Обзор | `cqa-dashboard` | Средний балл, грубые ошибки, «на проверку», где операторы теряют баллы, баллы по каналам и языкам, худшие диалоги |
| Диалоги | `cqa-dialog-list` | Фильтры (язык, канал, статус, набор, поиск), загрузка JSON, импорт набора по `group_id`, оценка выбранных / неоценённых / всех с прогрессом |
| Карточка | `cqa-evaluation` | Транскрипт с ролями, запись звонка с перемоткой на реплику, итог и секции, грубая ошибка с видом нарушения, по критерию: ступень шкалы, обоснование RU/KZ/EN, цитаты → переход к реплике, проверенный участок при пропущенном действии, причина Н/П, голоса оценщиков, апелляция и история решений |
| Апелляции | `cqa-review-queue` | Открытые/решённые: спорная оценка, комментарий, фрагмент диалога, решение «подтвердить / изменить» с причиной, итог «было → стало» |
| Чек-лист | `cqa-checklist-editor` | Критерии, секции, вес (контроль суммы 100), тип (да-нет / шкала со ступенями / флаг), Н/П с условием, «снижать / не снижать», замена критерия, сохранение версии и применение к диалогам |

Язык обоснований (RU/KZ/EN) — переключатель в шапке. `fetch` — только в `api.js`; общие помощники — `ui.js`.

## Сценарий защиты (5 минут)
1. **Обзор → Диалоги → карточка** звонка `p4-ru-001`: транскрипт, запись.
2. Раскрыть критерий: обоснование, клик по цитате (переход + перемотка), критерий с Н/П, проверенный участок, итог и секции.
3. «Оспорить оценку» → **Апелляции** → изменить с причиной → итог «было → стало» → в карточке видна история.
4. **Чек-лист** → «＋ Критерий» → «вместо какого» → сохранить версию → применить → карточка показывает оценку по новой версии.
